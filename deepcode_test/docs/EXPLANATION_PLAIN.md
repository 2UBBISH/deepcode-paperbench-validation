# DeepCode 到底靠不靠谱?——一次独立验证(白话版)

> 2026-08-27 · 对外讲解用。追问细节时翻精确版 `EXPLANATION_DRAFT.md`
> 结果段待 fre 判分后回填

---

## 一、为什么要做这件事

有篇论文叫 DeepCode,声称能**自动把学术论文变成可运行的代码**,效果碾压 Cursor、
Claude Code 这些商业工具。数字很漂亮:满分 1 分的评测里它拿 0.85,商业工具只有 0.4~0.6。

问题是,**这是作者自己报的成绩**。我们想知道:换个人、换个环境、用便宜的国产模型,
还能跑出这个效果吗?

## 二、我们怎么做的

### 第一步:先解决"谁来打分"

论文用 OpenAI 的 o3-mini 当阅卷老师。我们没有,只能换成 DeepSeek-V4-Pro。

**但换了老师,分数还能比吗?** 所以先考老师:官方提供了一批人类专家批过的标准答案,
拿来考我们这位老师,看它和专家意见多一致。

结果是每 3 道题批错 1 道左右。听起来不高?**人家的 o3-mini 在同一批题上也差不多**
——两者落在同一水平区间。

更有用的是发现了**批卷风格**:我们的老师**偏严**(专家给过 54% 的题,它只给过 45%),
而 o3-mini 偏松。这意味着**我们测出来的分数是偏低的**,如果最后成绩不如论文,
有一部分要算在老师太严上。

一个必须守住的边界:我们只考了老师一次,人家有 15 次的分布,所以只能说"不矛盾",
**不能说"水平一样"**。因此我们的分数**只能自己跟自己比**,不能直接对标论文那个 0.85。

### 第二步:先拿一篇论文试跑,把坑趟出来

选了 rice 这篇先跑通流程。结果发现**开源版的 DeepCode 在别人机器上根本跑不起来**,
修了一批工程缺陷:

- **配置缺失**:官方的初始化命令不生成自己流水线要用的工具配置,7 个得手工补,
  官方文档还漏列了 1 个;
- **模型兼容**:实测发现国产模型(Kimi)遇到**带连字符的工具名就无法正确调用**
  ——导致下载代码、切分文档这些环节的工具全部"静默失效",看起来在跑其实什么都没做;
- **代码缺陷**:下载环节的指令是一段**从没被接上的死代码**(整个项目里只定义、从没被引用);
  下载和分段的"成功"判定**不检查有没有真的产出文件**,失败了也报成功;
- **协议缺失**:论文说"上网时会拦截论文官方代码库,防止抄袭",
  但**开源代码里根本没有这个功能**,我们按官方黑名单文件补上了。

**要强调的是:这些修的全是"接不通"的工程问题,核心方法一个字没改**
(规划、检索、写码的逻辑和提示词都原样保留)。

rice 的成绩:**不用 CodeRAG 是 43.3 分,用了是 60.5 分,提升 40%**。
论文声称对非顶级模型有约 70% 提升——方向和量级都对得上。
而且同一篇论文里,Claude Code 只有 37.9、Cursor 41.9,
**我们用便宜国产模型的 60.5 比所有商业工具都高**。

但 rice 这条线**只能算"跑通流程的测试"**,不能当正式结论——那 60.5 是跨多轮拼凑的、
中途换过模型、参考资料还经过人工筛选,而且只跑了一次。

### 第三步:正式测量,选 fre 这篇论文

选它是因为论文对它的参考数据最全。三方设定:

**参照物**:用 Claude Code 本体(Sonnet 4.5,开思考模式)按官方任务书原文复现 fre,
全程不给任何提示。它对应论文里 Claude Code 的 0.6286 分,
用来标定我们的老师和论文的老师之间差多少。
有个意外发现:让它**独立跑了两次**,产出的代码**逐字节完全相同**(2,657 行)
——说明它在这道题上几乎没有随机性,这个参照物很稳。

**被测对象**:DeepCode + DeepSeek-V4-Pro 完整流程(含 CodeRAG,不做任何人工筛选语料),
跑了三轮,一轮因下载失败作废,**有效两轮**。

**阅卷老师**:全程固定不换。

## 三、结果

判定标准先说死:**论文自己同样配置跑三次,最好和最差差 0.15**。
所以任何小于 0.15 的差距都不算数,那是噪声。

| 对象 | 我们测得 | 论文对应值 |
| --- | --- | --- |
| 参照物(裸 Claude Code / Sonnet 4.5) | **0.4839** | 0.6286 |
| DeepCode + V4-Pro 第一轮(完整跑完) | **0.5184** | — |
| DeepCode + V4-Pro 第二轮(中途被掐断) | **0.4378** | — |
| DeepCode 两轮均值 | **0.4781** | 0.8435 |

判分质量已核验:三份均为 306 个叶子全判、官方 SimpleJudge 脚手架、code_only 口径、无失败判分。

### 结果:**没有复现论文声称的提升**

论文里 DeepCode 比 Claude Code 高 **1.34 倍**;我们测出来是 **0.99 倍——基本持平**。
两轮均值 0.478 对锚点 0.484,差 **-0.006**,远在噪声范围(0.15)之内,等于没有差别。
即便只看完整跑完的第一轮(0.5184),也只高出 0.035,同样在噪声内。

**→ 该效果在我们的条件下存疑。** 但这不等于"论文造假",因为混着三个拆不开的变量:
底座模型不同、我们没启用论文的自动纠错层、第二轮是被掐断的残次品(缺 README、依赖清单等)。

### 一个佐证:锚点验证了"老师偏严"是真的

我们的锚点 0.4839,论文同一位置是 0.6286,**低了 0.145**。
这与"我们的老师比论文的老师严"的独立测量结果方向一致、量级吻合
(逐题比对显示我们少给约 9 个百分点)。
说明锚点这个设计起作用了 —— 它把裁判差异从系统差异里分离了出来。

## 四、必须讲清楚的边界(不然会被问倒)

**第一,我们验证不了论文最核心的那个数字。** 论文说 DeepCode 比 Claude Code 强 1.34 倍,
那是**同一个模型**(Sonnet 4.5)分别裸跑和进 DeepCode 跑出来的。
而 Sonnet 4.5 没法接进 DeepCode(拿不到 API),所以我们的对比里混着模型差异,
**只能看方向,不能看倍数**。

**第二,V4-Pro 在论文里没有参考值。** 论文测过的是老一代的 DeepSeek-R1,不能代表 V4-Pro。
**它属于哪一档恰恰是这次要测的**——不能预设"国产模型弱"来给低分找借口。
旁证反而偏正面:它当阅卷老师和 o3-mini 打平,当考生时规划一次通过、索引零错误。

**第三,也是最重要的:这个评测只看"代码写得像不像",不看"跑起来行不行"。**
论文原文写明用的是 Code-Dev 协议,**不执行提交的代码**。评的四件事全是静态的:
语法对不对、依赖全不全、结构合不合理、算法实现是否忠实于论文描述。

所以论文成立的主张是:**能自动写出结构完整、算法忠实的代码库**。
它**没有证明**这代码跑起来能得到论文的数字——查遍全文,
**没有任何执行类实验、没有一个案例研究展示代码真跑出了原结果**,
而论文的局限性章节**也没提这一点**。
我们和论文用的是同一把尺子,所以对比公平;但这把尺子的天花板是双方共享的。

**第四,这不是数据集的问题,是论文的选择。** PaperBench 本身有三类题——
写得对不对(306 道)、跑不跑得起来(124 道)、结果对不对(7 道)。
**论文只用了第一类**,砍掉了另外两类。
而我们早就把完整复跑的环境准备好了,随时可以跑论文没跑的那部分,回答它回避的问题。
