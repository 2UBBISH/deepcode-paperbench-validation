# 通用发现:LLM 流水线的七种结构性失败模式

> 2026-09-02 · 从本次验证(生成侧 DeepCode + 判分侧 PaperBench SimpleJudge)中
> 提炼的可迁移模式。每条给出:模式定义 / 本项目实例 / 检测判据 / 通用修法。
> 适用于任何"多级 LLM 调用 + 程序化胶水"的流水线。

---

## P1 · LLM 作选择器,输出随输入规模增长 → 超预算即静默退化

**模式**:让 LLM 输出"从 N 个候选里挑出的清单",输出长度 ∝ N;
max_tokens 固定 → N 大到某阈值必然截断/为空,而调用方按"空=没有"处理。

**实例**:① CodeRAG 预筛(max_tokens=2000,151+ 文件仓库 100% 截断→回退全量);
② 裁判文件选择(51 文件目录树→返回空→`<files>`空→判 0)。
**同一模式在生成侧和判分侧各中一次。**

**判据**:grep 响应截断位置是否聚集在 max_tokens×4 字符附近;
选择器成功率与候选数做相关。

**修法**:输出改为"索引/ID 列表"而非全路径回显(输出长度 O(k) 不是 O(N));
或分页;或校验"响应完整性"(JSON 闭合)失败即显式报错而非回退。

## P2 · 测量失败与被测对象失败共用同一个零分

**模式**:判分器自身故障(拿不到输入、调用异常)产出的 0 分,
与"被测对象真的没做"的 0 分在结果里无法区分。

**实例**:`<files>` 为空时裁判写"no files provided → Score 0",解析为
`valid_score=True`;`valid_score=False` 只在抛异常时产生。
rice/trial3 有 7/32 个高权重叶被此误伤,总分被压低最高 0.086。

**判据**:抽样 0 分项的判语,统计"无输入/无法核实"类措辞占比;
按提交规模分层看该占比是否随规模增长。

**修法**:任何"输入为空/不可得"路径必须产出 NA(不计入分母)或 invalid,
而非 0;裁判提示词禁止在空输入上给出数值分。

## P3 · 静默兜底把失败包装成成功

**模式**:异常分支返回一个"看起来合法"的降级结果,只留一条 INFO,
下游与人类都无从察觉。

**实例**(一次验证里抓到四处):
① 规划三连败 → coerce 出通用假计划,标 status=success、completeness=1.0;
② 预筛截断 → "will use all files" 回退全量;
③ 仓库克隆失败 → 汇总照报 "N of M success" 继续跑;
④ 裁判文件读取异常 → except 后静默继续,空 `<files>` 进判分。

**判据**:审计所有 except/fallback 分支:降级后写入的状态字段是否与
正常成功不可区分;日志级别是否 ≤INFO。

**修法**:降级必须在持久化状态里留痕(如 source=coerced),
并在关键闸门处校验该痕迹(我们的"假计划闸"即此)。

## P4 · 二值评分无"无法核实"通道

**模式**:rubric 只有 0/1,裁判想表达"证据不足/没看到"时只能给 0,
系统性向下偏。

**实例**:178/306 叶全部 0/1 二值;P2 的误伤因此无法自我暴露。

**修法**:引入三值(0/1/NA)并把 NA 从分母剔除;或至少让裁判输出
`evidence_seen: bool` 字段供事后分层。

## P5 · 用"精确路径匹配"消费 LLM 输出

**模式**:LLM 返回文件路径/标识符,程序按精确(或简单子串)匹配消费;
LLM 的幻觉路径、大小写、前缀差异全部静默丢失。

**实例**:裁判选中 8 个文件只解析出 1 个(其余路径不存在→逐个吞异常);
预筛选中文件与仓库相对路径匹配同样脆弱。

**修法**:匹配失败时降级为 basename 匹配→模糊匹配→把未匹配清单
回灌给 LLM 重试一次;匹配率写入指标。

## P6 · 资源耗尽污染整批,产出"看似正常的数字"

**模式**:配额/余额在批处理中途耗尽,后续调用全部失败但按 P2/P3 处理,
最终报表仍是一组数值。

**实例**:402 余额耗尽 → 三份提交 161~168/178 叶 invalid,
仍各自报出 0.00~0.47 的"分数";若无 `num_invalid_leaf_nodes` 校验就会被采信。
**同坑踩过两次**(fre 一次、rice 一次)。

**修法**:批前做"接近真实单位成本"的探针(2000 token,不是 1 token);
批后强制校验失败率阈值(我们的判据:无效叶 ≤2);
大批拆小批,首批当金丝雀。

## P7 · 可复用提示词里硬编码上一个项目的领域先验

**模式**:提示词从旧项目移植,遗留具体领域词,静默扭曲所有新领域的行为。

**实例**:预筛提示词写死 "Focus on files related to recommendation systems,
graph neural networks, and diffusion models" —— 被测的是强化学习论文;
配套的默认 target_structure 也是推荐系统骨架(P3① 触发时被喂给筛选器,
导致 StateMask 191 个文件只留 1 个退火调度器)。

**判据**:grep 提示词模板中的名词性领域词;审查所有"默认值"常量的来源。

**修法**:领域相关内容一律从运行时输入注入;默认兜底结构改为领域中性
或直接失败。

## P8 · 冻结的中间产物把早期错误变成不可恢复

**模式**:流水线某阶段的输出(计划/schema/清单)一经产出即不可修订,
其中的遗漏被后续所有阶段忠实继承。

**实例**:Phase 5 文件树定死 → fre 两轮漏掉全部对比基线 → 三项满权重 0 分;
反事实显示仅此一项吃掉论文声称的全部增益(0.52→0.65)。

**修法**:给中间产物留修订通道(本项目 fix-①覆盖审计 / fix-②解冻文件树,
验证轮 trial_fx1 进行中);或至少加"产物 vs 源输入"的覆盖校验闸。

## 速查表

| # | 模式 | 一句话判据 | 一句话修法 |
| --- | --- | --- | --- |
| P1 | 选择器输出随输入涨 | 截断点聚在 max_tokens×4 字符 | 输出 ID 不回显全文;完整性校验 |
| P2 | 测量失败=0 分 | 0 分判语含"无输入" | 空输入 → NA,不进分母 |
| P3 | 静默兜底装成功 | 降级状态与成功不可分 | 降级留痕 + 闸门验痕 |
| P4 | 二值无 NA | rubric 只有 0/1 | 三值评分,NA 出分母 |
| P5 | 精确匹配吃 LLM 输出 | 选中数 ≫ 解析数 | 模糊降级 + 未匹配回灌重试 |
| P6 | 资源耗尽污染整批 | 批中途起全部同错 | 真实成本探针 + 失败率闸 + 金丝雀批 |
| P7 | 提示词领域残留 | 模板含具体领域名词 | 领域内容运行时注入 |
