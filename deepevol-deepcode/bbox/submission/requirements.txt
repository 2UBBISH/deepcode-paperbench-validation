# BBox-Adapter — "Lightweight Adapting for Black-Box Large Language Models"
# Dependency pinning derived from the paper's Appendix H.2 / environment description:
#   Python 3.10.13, AMD EPYC 7702 64-core CPU @1.50 GHz, NVIDIA A100-SXM4-80GB (CUDA 11.8+).
#
# Install:
#   python -m venv .venv && source .venv/bin/activate
#   pip install -r requirements.txt
#
# Notes
# -----
# * `torch` must be a CUDA build for A100 (cu118 or cu121 wheels). The CPU fallback works
#   for the offline self-tests (MockLLMClient + tests/) but not for real training runs.
# * BBox-Adapter itself only needs a single A100-80GB: the 0.1B/0.3B energy adapter
#   (DeBERTa-v3-base/large, BERT-base-cased) plus a black-box LLM served over the
#   Azure OpenAI REST API (no local weights).
# * The SFT-LoRA baseline (Mixtral-8x7B-v0.1) was trained on 4x A100-SXM4-80GB; the
#   half-precision Mixtral inference path needs ~90 GiB and therefore uses 2 GPUs
#   (device_map="auto").
# * The code degrades gracefully: with no Azure credentials / no `transformers` weights
#   available, `bbox_adapter.llm.blackbox_client` falls back to MockLLMClient and every
#   module remains importable.
