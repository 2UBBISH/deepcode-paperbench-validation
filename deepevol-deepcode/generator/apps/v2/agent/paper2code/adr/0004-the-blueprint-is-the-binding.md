# ADR 0004 · 蓝图本身就是绑定：Source 指针、节级阅读义务、回执只记录

日期：2026-09-20（夜）
状态：accepted；**取代 ADR 0003**（0003 原文保留作为历史）

## 背景

ADR 0003 在蓝图之外加了一层"原文义务"：planner 抽出义务条目（id / kind / 章节 / 逐字引文），再把每个文件绑到义务 id；host 定位引文、按锚点页签发回执、写前查收据、结束时整链审计并作为闸门。

09-20 用 PaperBench 20 篇 + SA-Bench 30 篇只跑 plan 阶段压测这一层，结果：

- 第一批 12/12 失败，全部死在标签层——kind 枚举、标题写法（`4.1.` 带点）、引文差一个字符（漏 `$`、`each with`/`each and`、`\mathbf{1}_{θ>…}` 抄成 `\mathbf{>…}`）、YAML 里的撇号 / 反斜杠 / 冒号、planner 撞 32768 输出上限截断、分段模式漏掉两个结构化键。每篇 30–56 条义务，每条 5–15% 抄偏概率，全对的概率趋近于零；重规划一次也是同一分布。
- 把校验放宽（同义词、模糊定位 ≥ 0.9、省略式引文、忽略字体类 LaTeX、块标量补救）后 37/44 通过，但每篇仍有 5% 左右义务定位不到；改成 JSON mode 单独一次绑定调用后格式问题消失，但又冒出锚点转述（模型没看到论文）、思考吃光输出预算、目录当文件、句末点粘进 id——每一类都是这层自己的问题。
- 分数上：fre-t14（只有 `Source: §x.y` 指针，无义务表）0.876；fre-t15（全套 0003）0.839，差在 planner 把 FB/SF 标 optional，与绑定无关。一篇看不出这层的收益。
- 根本的一点（owner 09-20 夜）："文件实现哪些义务"是模型的主观判断，host 只能验证"你读了你自己声称要读的地方"，验证不了"声称对不对"。多这一层判断，没有多一点可验证性，却多了一整套会坏的格式。

而蓝图第 2 节本来就把两样东西写在一起了：组件实现的**文件路径**和它来自论文的**章节**。

## 决定

绑定不再是独立产物，而是**蓝图第 2 节的读回**：

1. **Source 指针**：planner 在第 2 节每个实现论文内容的组件段落里写文件路径 + `Source: §x.y[, §z]`（节号或标题）。不抄公式、不抄 LaTeX、不写引文；只指节。glue 文件（包标记、配置加载、画图、README）不写。
2. **host 机械解析**（`source_fidelity.compile_manifest`，不问模型）：第 2 节按段落切；段落里出现的 `file_structure` 文件 → 绑到段落里解析成功的每个节；多段并集；指针解析不到的节记 `unmatched`；有指针没文件的段落记 `orphan`；第 2 节没提到的文件 = glue。产物 `source_manifest.json`：`files[path].sections`、`glue`、`unmatched`、`pointers`。
3. **阅读义务是节级的**：`read_paper(file_path=X)` 返回 X 的下一个未读绑定节（长节分页）；`write_file(X)` 放行条件 = X 的每个绑定节在**更早的模型回合**至少读过一页；否则 `SOURCE_READ_REQUIRED` 列出未读的节。plan 里没列的文件允许写，不绑。
4. **回执只记录**：实现结束的审计重放 trace（回执属不属于该文件、早不早于写、最终字节等不等于最后一次记录的写、树与计划的差），结果进事件 `implement.paper_fidelity` 和阶段记录，**不再让阶段失败**；`implementation_status` 闸只把它放进 detail。
5. **唯一的重规划条件**：整份蓝图一个 `Source:` 都没有 → 带原因重规划一次 → 仍没有 → 照跑（全 glue）。没被指到的文件是蓝图没规划，不兜底。
6. 删除：`source_items` / `source_files`、JSON 绑定调用、义务 id、锚点定位链、kind、unassigned 重规划、manifest_rejected 重规划、审计闸门。

## 否决的替代

1. **保留 0003 并继续放宽比对器**：放宽到 5% unmatched 之后仍有目录当文件、id 粘标点这类新问题，每一类修一次；且这层的判断本身不可验证。
2. **JSON mode 单独绑定调用**（试过）：格式 100% 了，但要把整篇论文塞进第二次调用（否则锚点是转述），思考共享输出预算，多一次调用多一类失败；而它产出的信息（文件 ↔ 章节）第 2 节已经有了。
3. **退回 t14 v1（只有指针、无表、无强约束）**：丢掉了"这个文件写前该读哪一节"这条机器可用的信息，`write_file` 无从检查。本决定与它的差别只是 host 把指针读回来并在写前执行。

## 后果

- planner 输出体量：fre 从 45k 字符（0003 含两份公式复印件）降到约 20k；再无撞输出上限的路径。
- 写码 agent 每写一个"论文文件"多读 1–3 节原文（fre-t15 平均 2.5 次 / 文件）；读的是整节，不是锚点页。
- 审计不再阻断：一个写在计划外的文件、一次没读就写（工具层本已拒绝）只会出现在 `violations` 里。
- `plan.fidelity` 统计里的 `structured_source_items/files` 恒为 0（保留字段以免下游报错）；`plan.source_manifest` 事件字段改为 `files / paper_files / glue / pointers / orphan_pointers / unmatched / replans`。
- 0003 引入的词（原文义务、引用证据、保真门禁、合规修复轮）从 CONTEXT.md 移除；保留并重定义：Source 指针、阅读义务、回读回执。
